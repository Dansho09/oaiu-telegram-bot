# OAIU Assistant · Cloudflare

Полная версия Telegram-бота для Cloudflare Workers Free. Ноутбук и постоянно запущенный Python-процесс не нужны. Telegram отправляет сообщения через защищённый webhook; SQLite-backed Durable Object хранит диалог, до 10 черновиков на пользователя, исходящую почту и задания. Alarms продолжают очередь после пауз и перезапусков. Платные KV, R2, D1, Queues и внешний сервер не требуются.

Сохранены форматы текстов, русский / қазақша / English, выбор объёма и тона, редактирование, переводы, история, TXT, отмена и удаление собственных данных с подтверждением. Доступ открыт всем при пустом `BOT_ACCESS_CODE`. Лимит Groq обрабатывается в фоне: пользователь видит «Готовлю текст…», затем ответ.

## Сценарии и справочник

Рабочая Cloudflare-версия расширена: волейбол, другие спортивные события, Ұстаздар күні, посвящение и произвольное мероприятие. Можно выбрать от **15 минут до 8 часов**, время начала, 1–4 ведущих, их имена, выход справа/слева (со стороны зрителя), спортзал или свой маршрут. Кнопки подтверждения можно заменить сообщениями «Продолжить» / «Жалғастыру», тон — «Тёплый» / «Жылы», выбор людей завершить словом «Готово» / «Дайын». Точные интервалы, подписи ведущих и ремарки формирует программа. Groq `openai/gpt-oss-120b` возвращает структурированные реплики; отдельный аккаунт OpenAI не нужен. Матчевое время — оценка, реальный регламент согласует организатор с судьями.

`/people` открывает справочник: ректор, два проректора, два декана и восемь заведующих кафедрами. Можно выбрать до шести человек или добавить участника только для своей задачи. Упоминание ректора подставляет ФИО; неоднозначный декан/заведующий предлагает выбор. Имена в старых черновиках сохраняются вместе с исходными данными.

Структура двух предоставленных сценариев использована как редакционный ориентир. Оригинальные DOCX, списки студентов, награждаемых и исполнителей не публикуются. Деканы и кафедры внесены из предоставленного справочника от 29.10.2026, руководство сверено с [сайтом университета](https://caiu.edu.kz/). Источники конкретных записей указаны в `src/directory.js`. Назначения могут меняться; владелец обновляет справочник.

### Панель владельца

Добавьте закрытый секрет `BOT_OWNER_USERNAME` (имя без @) через `wrangler secret put BOT_OWNER_USERNAME`. Затем с указанного аккаунта отправьте боту `/admin`. Бот проверит отправителя Telegram и один раз закрепит его числовой ID. После этого смена username не лишает владельца доступа, а повторное использование его старого username другим аккаунтом не даёт прав.

Панель позволяет редактировать/добавлять общие ФИО и должности, отменить последнее изменение и смотреть суммарные счётчики. Чужие тексты не показываются. Кнопка и команда `/admin` добавляются только в личный чат владельца; общий список команд её не содержит. Все действия повторно проверяют числовой ID отправителя, в том числе callbacks. Пустой секрет отключает первоначальное назначение. Защищённые HTTP-маршруты миграции не используются для этой панели.

## Бесплатный тариф

Нужен аккаунт Cloudflare с Workers Free. SQLite-backed Durable Objects доступны на Free. Действуют дневные квоты запросов, вычислений и операций хранилища; при исчерпании запросы могут завершаться ошибкой до сброса квоты. Это не обещание неограниченной нагрузки. Groq имеет отдельные лимиты.

- [Workers: тарифы](https://developers.cloudflare.com/workers/platform/pricing/)
- [Durable Objects: бесплатные квоты](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- [Alarms: гарантии и повторы](https://developers.cloudflare.com/durable-objects/api/alarms/)

## Подготовка

Требуется Node.js 24+ для локальных тестов. У рабочего бота нет npm-зависимостей; Wrangler нужен для разработки и публикации.

```sh
cd cloudflare
pnpm install
pnpm test
pnpm run check
```

`src/ui.js` содержит тексты интерфейса и редакционные правила Python-версии. `src/core.js` — диалог и SQLite. `src/worker.js` — webhook, доставка, генерация и фоновые задания. `src/scenario.js` — точный тайминг и постановка; `src/directory.js` — справочник; `src/admin.js` — права владельца и редактор справочника. `wrangler.jsonc` использует SQLite-backed namespace (`new_sqlite_classes`), совместимый с Free.

## Перенос работающего бота

1. Остановите прежний экземпляр. Сохраните актуальную базу SQLite вместе с WAL или сделайте согласованную SQLite backup. Не используйте старую локальную копию, если на сервере появились новые тексты.
2. Авторизуйте официальный Wrangler в нужном аккаунте Cloudflare и опубликуйте Worker:

   ```sh
   pnpm exec wrangler login
   pnpm run deploy
   ```

3. Создайте **вне Git** приватный JSON-файл с ключами `TELEGRAM_BOT_TOKEN`, `GROQ_API_KEY`, `TELEGRAM_WEBHOOK_SECRET` и временным `MIGRATION_TOKEN`. Два последних значения должны быть независимыми криптографически случайными строками не короче 32 символов. Секрет webhook допускает только буквы, цифры, `_` и `-`. Ограничьте права файла. Значения `GROQ_MODEL` и публичного режима уже заданы в конфигурации; модель при необходимости замените на доступную вашему аккаунту Groq.
4. Загрузите этот файл как **секреты**, а не открытые переменные:

   ```sh
   pnpm exec wrangler secret bulk /PRIVATE/PATH/cloudflare-secrets.json
   ```

5. Экспортируйте историю и импортируйте её один раз в пустое хранилище. Файл содержит личные тексты и должен оставаться приватным:

   ```sh
   python3 scripts/export_sqlite.py /PRIVATE/PATH/oaiu.sqlite3 /PRIVATE/PATH/migration-data.json
   node scripts/import.mjs https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev /PRIVATE/PATH/cloudflare-secrets.json /PRIVATE/PATH/migration-data.json
   ```

   Импорт сохраняет сессии, черновики, доступ и незавершённые задания. Повторный импорт и перезапись непустого бота запрещены. Незавершённые задания могут начать выполняться после импорта.

6. Подключите Telegram без удаления ожидающих обновлений:

   ```sh
   node scripts/activate.mjs https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev /PRIVATE/PATH/cloudflare-secrets.json
   pnpm exec wrangler secret delete MIGRATION_TOKEN
   ```

   Затем проверьте `/start`, генерацию, правки, историю и TXT с телефона. Удаление временного секрета закрывает оба административных маршрута. Тексты и ключи не публикуются в GitHub.

## Надёжность и ограничения

Входящее обновление и исходящие сообщения сохраняются транзакционно до ответа Telegram. Повтор одного update не меняет диалог второй раз. Генерация выполняется по одному запросу; отменённый ответ не записывается в историю. Сетевые ошибки повторяются с паузой, лимиты Groq ждут сохранённого срока. Готовый текст сохраняется до доставки и доступен в истории.

Telegram не предоставляет ключ идемпотентности для `sendMessage`: при обрыве сети после принятия сообщения, но до подтверждения, редкий повтор доставки возможен. Webhook принимает только сообщения с корректным секретным заголовком; миграция защищена отдельным временным секретом. Публичная проверка `/health` не раскрывает переписку или ключи. Подробные логи запросов и observability по умолчанию выключены.

База SQLite остаётся на прежнем сервере как резервная копия. Для возврата сначала удалите webhook без сброса ожидающих обновлений, затем восстановите актуальную историю и включите только один Python-экземпляр. Старый сервер с истёкшим бесплатным тарифом сам по себе не запустится.
